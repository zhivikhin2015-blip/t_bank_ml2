# Технический повтор окончательной оценки

Первый окончательный прогон остановился до расчёта результатов первой политики: PyTorch/MPS не поддержал сравнение `int64` дат доступности каталога с `uint32` timestamp из Parquet. Reward-исходы новой когорты к этому моменту уже были прочитаны. Выбор моделей, параметры и веса были зафиксированы до первого доступа и после ошибки не менялись.

Для повторения используется `technical_retry.py`. Он приводит `uid` и `timestamp` к `int64` в памяти и проверяет точное совпадение численных значений. Сохранённые данные, первоначальный `frozen.json` и первоначальный исходный код остаются неизменными. Хеш адаптера и причина повтора записаны в `technical_retry.json`. При каждом повторе проверяются первоначальные входы и дополнительный манифест адаптера.

Для данного запуска и свежего воспроизведения после стадии `freeze` используйте следующие завершающие команды:

```bash
.venv/bin/python -B scripts/reproduce.py run holdout
.venv/bin/python -B scripts/reproduce.py run audit
.venv/bin/python -B scripts/reproduce.py run serving
.venv/bin/python -B scripts/reproduce.py run report
```

Этап holdout подготавливает `holdout.npz` только после проверки frozen-манифеста. Адаптер использует тот же набор численных значений и то же замороженное сравнение. Повтор исправляет вычислительную ошибку; он не является подбором по окончательной выборке. При свежем воспроизведении эти команды позволяют сразу использовать совместимую репрезентацию, без повторения известного сбоя исходной команды `research_v2.run holdout`.

После сохранения всех результатов технический адаптер завершился с ошибкой финального журналирования: поле `reason` конфликтовало с именем аргумента логгера. `research_v2_runtime.py` устраняет только этот конфликт имени. Его собственный хеш и проверка неизменности входов находятся в `runtime_driver.json`. Первоначальные frozen-источники и первоначальный адаптер не переписываются. Завершённые результаты проверяются по контрольным суммам и при повторе не пересчитываются.

`research_v2_serving.py` выполняет отдельный технический замер эквивалентного инференса на C. `research_v2_finalize.py` вызывает замороженный генератор отчёта, добавляет технические пояснения и измеренные затраты, затем обновляет архив. Контрольные суммы численных результатов и исходного frozen-манифеста до и после оформления проверяются. Это позволяет воспроизвести окончательный документ, включая описание технического повтора.

Исходные имена модулей в описании относятся к воспроизводимой рабочей копии. Канонический код расположен в `src/`; зафиксированные протоколы и журналы технических повторов — в `results/research_v2/`.
