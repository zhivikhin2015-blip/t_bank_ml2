# RL-рекомендации на Yambda: проверка оптимизации и переноса между пользователями

## Результат и границы вывода

Обучены новые модели отклика, шесть RL-пилотов H=1, повторения выбранных настроек, SFT-контроли и политики H=5. Исходные GPT-2 seeds 11/22/33 переиспользованы после проверки данных, исходного кода и весов; их полное повторное обучение в этом запуске не выполнялось.

Окончательная проверка содержит 9868 событий 432 ранее неиспользованных пользователей. Их исходы прочитаны после фиксации моделей и кода. Это проверка переноса между пользователями в том же периоде D. Данные не дают нового независимого временного периода: за прежней границей доступны только 15 секунд. Исходный D прежней когорты уже был просмотрен при разработке. Перенос на новый временной режим не установлен.

Reward model показала неподтверждённое преимущество по MSE над общим средним: разница MSE -0.003641, парный 95%-й интервал [-0.007649; +0.000375].

Для seed 11 выбранный RL по доле изменил ожидаемую модельную долю на +0.00634 (+0.63 процентного пункта). RL по времени изменил ожидаемый суррогат времени на +2.28 с. Эти величины рассчитаны замороженной reward model, не измерены на показах новой политики.

ratio: средняя разница NDCG@10 -0.000455, парный 95%-й интервал [-0.000901; -0.000004]. Контраст с 95% исходного NDCG: нижняя односторонняя 95%-я граница +0.000029; сохранение порога подтверждено в рамках данной условной проверки. Стандартное отклонение разниц между тремя training seeds: 0.000188.

time: средняя разница NDCG@10 -0.000044, парный 95%-й интервал [-0.000306; +0.000215]. Контраст с 95% исходного NDCG: нижняя односторонняя 95%-я граница +0.000581; сохранение порога подтверждено в рамках данной условной проверки. Стандартное отклонение разниц между тремя training seeds: 0.000063.

## Техническое восстановление окончательного прогона

Первый прогон остановился при сравнении uint32 timestamp с int64 датами каталога. Reward-исходы к этому моменту были прочитаны, результаты первой политики ещё не рассчитаны. Приведение типов проверено на точное совпадение численных значений. После сохранения всех вычислений отдельно исправлен конфликт имени поля финального журналирования. Первоначальный frozen-манифест, вычислительные источники, данные и веса сохранены; дополнительные адаптеры имеют собственные хеши и журналы. Выбор моделей после доступа к этой выборке не менялся. ## Данные и временной протокол

Используется Yambda-50M, версия `dd6f3a19eef5866e346c3270e098baa641a44948`, SHA-256 исходного Parquet `eed9cbd094af1e189507d2f8132a0dc9653b90e65480125c7cdccd601e0592d1`. Каталог из 5000 объектов рассчитан только по A исходной когорты. История содержит последние 64 ID; неизвестные объекты представлены UNK. Неизвестные цели остаются в оценке и считаются промахами. Ранжируется полный допустимый каталог без sampled negatives; равные оценки упорядочиваются по token ID.

На A обучаются политики и модели отклика. B1 выбирает архитектуру и checkpoint reward model по macro-user MSE; из B1 исключены отклики, пересекающие его правую границу. На B2 обучается неотрицательная линейная калибровка с clip(0,1). C выбирает RL и пересортировку. После фиксации выполняется проверка новой когорты в D. Правила зрелости откликов, неоднозначных timestamp и ограничения числа целей записаны в `protocol.json` и `data_manifest.json`.

Исходные 1024 пользователя исключены из резервирования новой когорты. Зарезервированы следующие 512 ID в SHA-256 порядке; 434 соответствуют требованию 20 событий A. Отбор пригодности использовал только прошлую активность. Однако исходный Yambda сам отбирает пользователей по активности в раннем и последующем периодах, поэтому выводы об удержании ограничены этой популяцией. [Описание данных и отбора](https://arxiv.org/html/2505.22238v1).

## Reward model

MLP использует замороженное представление истории GPT-2, обучаемый embedding объекта и длительность. Проверены варианты без истории и без длительности. Для каждого варианта выполнены 4000 обновлений; выбран checkpoint с минимальной MSE на B1. Лучший вариант — `reward_history_duration_s11`. Архитектура диагностического оценщика такая же; другой seed и исходная GPT-2 дают отдельную инициализацию. Общие ошибки данных и постановки могут сохраняться.

Обучение MSE и калибровка дают равный полный вклад пользователям. Baselines рассчитаны по тому же train-набору. Ошибки ниже относятся только к известным логированным объектам: 3008 событий, 407 пользователей.

## Политики, цели и метрики

GPT-2 имеет два блока, четыре головы, скрытую размерность 128, случайную исходную инициализацию и словарь item ID. REINFORCE сэмплирует четыре независимые цепочки на исходную историю. Используются leave-one-out baseline, замороженный оценщик, отключённый dropout, точный KL к исходной GPT-2 и его прямая производная; будущие KL входят в return. Корректность градиента проверена точным перечислением двухшагового примера. [REINFORCE](https://doi.org/10.1007/BF00992696).

Награды: R1 — откалиброванная доля; R2 — min(duration,cap)/cap × R1; R3 — R2 минус 0.1 за повтор внутри цепочки. R2 ограничивает длительность объекта, а не непосредственно фактическое время прослушивания. Повторы реальной истории разрешены. H=5 безусловно добавляет предложенный ID в контекст; отклик и прекращение сессии не моделируются.

Для H=1 проверена точная политика pi_star(a|h) proportional pi_ref(a|h) × exp(reward/beta), beta>0. Для фиксированного контекста J(pi)=beta log Z - beta KL(pi||pi_star); поэтому она максимизирует модельную цель среди произвольных распределений действий. Она не гарантирует сохранение NDCG, требует оценки полного каталога и не доказывает улучшение реальных откликов.

Пересортировка меняет оценки top-100 исходных объектов. При оценке ожидаемой награды её sampling-политика нормируется по этим 100 объектам; поэтому вес 0 сохраняет ранжирование, но не полное распределение исходной GPT-2. Аналитическая политика использует весь каталог. Выбранные на C веса: ratio=10, time=3.

Recall@K при одной цели равен индикатору попадания; NDCG@K — 1/log2(rank+1) при попадании и 0 иначе. Сначала метрики усредняются по событиям пользователя, затем по пользователям. Expected reward — полная сумма вероятности действия × его модельной награды. Reward@10 — отдельное равномерное среднее списка. J сравнивается только при одинаковых награде и beta. Для H5 его одноступенчатая диагностика не заменяет полный rollout return.

## Возвращение после конца сессии

Сессии определены разрывом более 30 или 60 минут. Момент определения конца сессии — последнее событие плюс этот разрыв. Цель — следующее взаимодействие до конца полного семидневного окна от последнего события. Незрелые окна исключены. Модель прошлой активности использует длину завершившейся сессии и число прошлых действий за день и неделю; преобразования и 500 обновлений логистической модели обучаются на A. Это описательный development-эксперимент; сигнал не использовался как RL-награда.

AP рассчитан с macro-user весами для отрицательного исхода; равные оценки обрабатываются группами. Постоянный предиктор имеет AP, равный доле отрицательных исходов. Предсказуемость будущей активности не устанавливает влияние рекомендации. Для оптимизации удержания потребуются модель реакции и прекращения взаимодействия, валидные данные показов либо онлайн-проверка. [Связанный сессионный подход](https://arxiv.org/html/2607.02818v2).

## Вычисления и воспроизведение

Устройство новых запусков: mps, PyTorch 2.14.1, четыре CPU-потока. Технический warm-cache замер: медиана RL-шага с повторным кодированием 0.06578 с, с общим вычислением исходной истории 0.02653 с; ускорение 2.48 раза. Проверка эквивалентности: максимальное расхождение градиентов 1.64e-09. Для технического замера использована случайно инициализированная reward-head; это не результат обучения политики.

Сумма новых обучающих обновлений: 25.53 мин; повторное исходное GPT-2-обучение, подготовка признаков, checkpoint I/O и оценка не включены. Время окончательного инференса и вычисления метрик: 4.65 мин; первоначальная подготовка полных reward-score кешей учитывается в access log отдельно. ## Ограничения и следующий эксперимент

Исследование использует ограниченный популярный каталог, маленькую GPT-2 и отобранную активную популяцию. Точный порядок внутри пятисекундных групп неизвестен. Reward model проверена на известных логированных объектах, а многократное продолжение создаёт состояния без наблюдаемых истинных откликов. Диагностический оценщик разделяет данные и архитектуру с основным. Проверка новых пользователей не заменяет новый временной период. Для дальнейшего подтверждения нужны независимый будущий период, более широкий каталог с проверкой доступности объектов и онлайн-оценка реальных показов.

## Дополнительные проверки стоимости и интерпретации

Инференс измерен отдельно от метрик качества на фиксированных контекстах C: 5 прогревочных и 20 измеряемых вызовов каждого метода, четыре CPU-потока. Устройство замера — mps. Медианы ниже относятся ко всему batch, без загрузки весов, сети и затрат сервиса.

| Метод | Batch 1, мс | Batch 32, мс |
|---|---:|---:|
| База | 3.36 | 4.81 |
| RL по доле | 3.30 | 4.78 |
| RL по времени | 3.29 | 4.87 |
| Аналитическая: доля | 4.73 | 16.43 |
| Аналитическая: время | 4.11 | 19.06 |

`research_v2_serving.py` проецирует в item logits только последнее скрытое состояние. На 64 development-контекстах максимальное расхождение logits трёх акторов равно 0, top-20 совпадают полностью. Аналитическая политика разделяет один Transformer-проход с reward model: идентичность encoder-весов проверена. Замер включает вычисление награды полного каталога для аналитической политики; кеш результатов разных запросов не используется. Это технический warm-cache замер, а не подтверждённая задержка рабочего сервиса.

Бюджет H5 при 200 обновлениях проверен независимо: 64 000 действий, как у H1 при 1000 обновлениях. Сопоставление времени приблизительное. Отклонения ближайших стадий R1/R2/R3: +0.99%, -22.00%, -21.48%. Они не позволяют считать затраты строго равными; более частое сохранение стадий нужно в следующем заранее заданном эксперименте. Полные значения находятся в `budget_audit.json`.

Дополнительный диагностический контраст повторений R3−R2 на шаге 5: -0.00977 (-0.98 процентного пункта), 95%-й интервал [-0.01432; -0.00521]. Он относится к искусственным траекториям.

Предиктор возвращения использует прошлую активность, без ID предлагаемого объекта. Добавление p_return(h) к одноступенчатой награде не меняет предпочтение действий: это одинаковый для всех a член, а сумма производных вероятностей действий равна нулю. Для направленной оптимизации возвращения нужен сигнал, зависящий от действия и реакции, например p_return(h,a,feedback), с отдельно проверенными моделями отклика и прекращения сессии.

Награды первоначальной и новой версий напрямую несопоставимы: изменились оценщик, калибровка, популяция и переход от reward@10 к полной ожидаемой награде. Первое наблюдение объекта в A — консервативный прокси его доступности, без известной даты появления в каталоге. Задержки исходного логирования не документированы полностью; timestamp-проверки не заменяют знания эксплуатационного процесса.

Близкая постановка beyond-accuracy целей рассмотрена в [Petrov и Macdonald, Aligning GPTRec with Beyond-Accuracy Goals with Reinforcement Learning](https://arxiv.org/html/2403.04875v1). В ней применяются PPO и обучение через teacher; текущий эксперимент использует прямое next-item обучение и REINFORCE, без заявления о воспроизведении той статьи.
